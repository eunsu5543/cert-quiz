## 핵심 제약 — 저작권 (B′: 직접 소스 + 안전게이트)

- 교재 PDF는 **repo 트리 바깥**(`C:\Docs\nhn`)에 두고 절대 commit/push하지 않는다.
- 교재에서 추출해 repo에 저장하는 것은 **사실·구조뿐**: 섹션 목차, 섹션별 페이지 수
  (=강조 비중), 토픽 목록. 고유 표현·연습문제 원문은 저장/배포 금지.
- 생성되는 모든 배포 문제는 **공개 출처로 독립 검증 가능**해야 한다:
  - 일반 개념 문제 → "일반 공개 클라우드 지식"으로 그라운딩(관대; 업계 표준 사실)
  - NHN 특정 문제 → 공개 NHN 사용자 가이드로 그라운딩
- 교재 연습문제는 **베끼는 소스가 아니라 avoid 기준**(유사본 reject)으로만 사용.

## 작업 (우선순위)

1. **concept-security 보강** — 교재 §1(p3–38)을 비전으로 읽어 일반 클라우드 개념
   토픽(온프레미스/클라우드 정의, IaaS/PaaS/SaaS, 책임공유 모델, 가용성·확장성,
   일반 보안 개념 등)을 식별. 그 토픽으로 문제 생성하되 **일반 공개 지식으로
   그라운딩**(검수기 게이트). 목표: 29 → 공식 15% 수준(전체 규모에 맞춰 ~40+).
2. **billing 보강** — 교재 §6(p137–152)의 요금/크레딧/약정/과금모델 토픽 식별 후
   공개 가이드+일반 요금개념으로 생성. (현재 진행 중인 billing 배치 결과와 합산.)
3. **NCS 과집중 정리** — 교재가 컨테이너를 거의 안 다루면(쿠버네티스는 별도 과정),
   service-skill의 K8s-깊이 문제 3~4개(디플로이먼트vs스테이트풀셋, init 컨테이너,
   ConfigMap/Secret) 제거/교체 검토.

## 파이프라인 통합

기존 cert-batch 파이프라인 재사용. 변경점:
- **검수기 루브릭에 그라운딩 게이트 추가**: "이 문제의 사실이 공개 출처(일반 클라우드
  지식 또는 공개 NHN 사용자 가이드)로 뒷받침되는가? 교재에만 있는 고유 표현/연습문제
  유사본인가?" → 후자면 reject.
- concept-security 생성기 소스에 "교재 §1에서 식별한 일반개념 토픽 목록"(사실)을
  힌트로 제공하되, 출처는 공개 지식으로 작성하도록 지시.
